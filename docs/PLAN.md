# PII Guard — план разработки

Рабочий документ проекта: решения, архитектура, контракт, задачи. Код пишет alfagen по заданиям
из раздела «Задачи», и этот файл — общий контекст для всех заданий.

## Задача

Модуль безопасности персональных данных (трек AlfaGen) — прокси между системой-потребителем и LLM.
Находит ПД в запросе, маскирует их перед отправкой в LLM и восстанавливает исходные значения в ответе.

## Обязательные проверки

1. **Качество кода.** Сдаём zip только с исходниками: без .venv, node_modules, build, датасетов, .git.
   Ориентир — правила SonarQube: сложность функций, дубли, секреты в коде, небезопасные хэши и ГПСЧ.
2. **Нагрузочный прогон `POST /process`** (контракт — [process_api.yaml](process_api.yaml)):
   - ~5 минут, целевые 1000 RPS; элементы датасета повторяются, у каждого элемента в прогоне свой `payload_id`;
   - таймаут запроса 10 с, до 2 ретраев на запрос, 429 с `Retry-After` допустим;
   - после 5 невалидных ответов подряд прогон останавливается (429 невалидным не считается);
   - эталонной маски нет: маску сравнивают с исходной строкой по span-based метрике,
     демаскированный текст — с исходной строкой;
   - пропуск ПД штрафуется сильнее лишней маски; частично открытые символы немного снижают оценку;
     способ и длина маски не важны; маскировать служебные слова («серия», «ул.», «года») — штраф;
     если весь payload — одно значение, полная маска строки не штраф;
   - в датасете 17 категорий: отдельные слова, фразы и предложения;
   - нагрузка с разгоном: в среднем ~330 RPS, пики до 1000, до 200 соединений, каждое ждёт ответа;
     429 не ошибка, но попадает в статистику; смотрят среднее, p50, p95, p99;
     демаскирований столько же, сколько маскирований, на демаскирование приходит наша маска.

## Требования, которые влияют на код

- 17 типов ПД (таблица ниже), список расширяемый, поиск не зависит от регистра.
- Вариации написания: регистр, порядок дня/месяца/года, дата словами, разделяющие слова («серия … номер …»).
- Не ПД: известные люди («поэт Александр Пушкин»), адрес отделения банка.
- Демаскирование восстанавливает текст с сохранением позиций знаков.
- Ограниченный список систем-потребителей; по каждой системе настраиваются: вкл/выкл, типы ПД,
  демаскирование, вид маски.
- Подробные логи этапов и найденных типов ПД — без самих ПД. Метрики Latency, RPS, TPS.
- Latency ≤ 1 с (цель жюри — ≤ 0,5 с) при 1000 RPS; тексты до 100 000 токенов.
- Деградация при недоступности компонентов, понятные сообщения об ошибках.
- README с описанием настроек и инструкцией по настройке не длиннее 5 предложений.

## Решения

- Python 3.11, FastAPI, gunicorn + uvicorn-worker, orjson, pydantic v2.
- Соответствия `payload_id` → замены хранятся в Redis: AES-256-GCM, TTL, без записи на диск.
  Если Redis недоступен — память процесса и флаг деградации в `/ready`.
- Поиск ПД только локальный: регулярные выражения, валидаторы (алгоритм Луна, контрольные суммы),
  контекстные слова, морфология pymorphy3 (теги Name/Surn/Patr/Geox). Внешние LLM и тяжёлые
  NER-модели в пути запроса не используются.
- Нормализация сохраняет длину: `norm[i]` соответствует `text[i]`, поэтому позиции спанов общие
  для исходного и нормализованного текста.
- Текст вне найденных ПД не меняется ни на символ. Слова-метки («паспорт», «ИНН») в спан не входят —
  маскируется только значение.
- Маскирование детерминировано: одинаковый вход и профиль дают одинаковую маску.
- Настройки систем и типов ПД — YAML в `config/`, перезагрузка без рестарта.

## Архитектура

```
Система-потребитель
   │ POST /v1/chat/completions (X-API-Key)
   ▼
Модуль ПД: allowlist → нормализация → распознаватели → скоринг контекста
           → политика системы → маскирование → повторная проверка на утечку
   │ только замаскированный текст
   ▼
LLM (OpenAI-совместимый API, шлюз alfagen; заглушка при недоступности)
   │ ответ с масками/токенами
   ▼
Модуль ПД: демаскирование (если разрешено системе) → Система-потребитель

Рядом: Redis (соответствия, AES-GCM, TTL) · YAML (системы, типы ПД, правила)
       · JSON-логи без ПД · Prometheus + Grafana
```

Точки входа:

| Эндпоинт | Назначение |
|---|---|
| `POST /process` | контракт проверяющей системы; без ключа (так требует контракт), профиль `checker` |
| `POST /api/v1/mask`, `POST /api/v1/unmask` | маскирование и демаскирование для систем-потребителей (`X-API-Key`) |
| `POST /v1/chat/completions` | OpenAI-совместимый прокси к LLM |
| `GET /ui` | демо-страница |
| `GET /metrics`, `/health`, `/ready` | метрики Prometheus, живость, готовность |
| `/admin/*` | перезагрузка конфига, вкл/выкл систем (админ-токен) |

## Модель данных

```python
@dataclass(frozen=True, slots=True)
class Span:                 # найденный фрагмент ПД; позиции в исходном тексте
    start: int
    end: int                # не включительно
    pii_type: str
    score: float            # 0..1
    recognizer: str
    part: str | None = None # для ADDRESS: country / postal_code / region / city / street / house / apartment

@dataclass(frozen=True, slots=True)
class Replacement:          # одна выполненная замена
    start: int              # позиция в исходном тексте
    end: int
    masked_start: int       # позиция в замаскированном тексте
    original: str
    masked: str
    pii_type: str

@dataclass(frozen=True, slots=True)
class MaskResult:
    text: str
    replacements: tuple[Replacement, ...]

@dataclass(frozen=True, slots=True)
class MappingRecord:        # то, что хранится по payload_id (зашифрованным)
    original_fp: str        # HMAC-SHA256 исходного текста, hex
    masked_text: str
    replacements: tuple[Replacement, ...]
```

Исходный текст целиком не хранится: он однозначно собирается из `masked_text` и `replacements`.

## /process — машина состояний

Ретраи проверяющей системы повторяют запрос с тем же `payload_id`, поэтому направление определяется
не только по наличию записи:

```
записи нет                      → маскируем, сохраняем MappingRecord (SET NX), отдаём маску;
                                  если параллельный дубль успел раньше — отдаём его маску
HMAC(payload) = original_fp     → повтор маскирования → та же маска
payload = masked_text           → демаскирование и его повторы → исходный текст
иначе                           → текст изменён (например, LLM) → замена замаскированных фрагментов
```

Если ПД не найдено, маска совпадает с исходником, и обе ветки отдают одну и ту же строку.

## Виды маски

- **full** — вид для профиля `checker`: каждый символ значения, включая разделители, заменяется
  на `*`, длина сохраняется. «Иванов Иван Иванович» → 20 звёздочек. Открытых символов нет, а в маске
  нет букв и цифр, которые могли бы совпасть с оригиналом при посимвольном сравнении.
- **partial** — для систем-потребителей, в стиле примера из контракта. Значимыми
  считаются буквы и цифры: первые `keep_start` и последние `keep_end` значимых символов остаются,
  остальные значимые заменяются на `*`, прочие символы (пробелы, дефисы, скобки, точки) сохраняются.
  Пример: «4509 123456», 2/2 → «45** ****56».
  - PERSON и CARDHOLDER — инициалы: каждое слово → первая буква в верхнем регистре + «.», через пробел.
    «Иванов Иван Иванович» → «И. И. И.».
  - EMAIL — первый символ локальной части остаётся, остальное до `@` → `*`, домен без изменений.
- **label** — `[ПАСПОРТ]`.
- **token** — `[ФИО_1]`: номер растёт по типу для каждого нового значения, одинаковые значения
  получают один токен. Основной вид для LLM-прокси: смысл запроса сохраняется, демаскирование точное.

Параметры partial по типам: PASSPORT 2/2, CARD_NUMBER 4/4,
PHONE 1/2, INN 2/2, DRIVER_LICENSE 2/2, SNILS 0/2, остальные 0/0.

## Профили систем (черновик `config/systems.yaml`)

```yaml
defaults:
  mask_style: token
  unmask: true
  strict: false
systems:
  checker:                  # профиль POST /process; по контракту без ключа
    enabled: true
    pii_types: all
    mask_style: full
  crm-assistant:
    enabled: true
    api_key_sha256: "<sha256 ключа>"
    pii_types: all
    strict: true            # ниже пороги + повторная проверка перед LLM
  marketing-bot:
    enabled: true
    api_key_sha256: "<sha256 ключа>"
    pii_types: [PERSON, PHONE, EMAIL, CARD_NUMBER, PIN]
    mask_style: label
    unmask: false
    rules:
      - type: PIN
        requires_any: [CARD_NUMBER]   # ПИН маскируем только вместе с номером карты
  legacy-crm:
    enabled: false
```
